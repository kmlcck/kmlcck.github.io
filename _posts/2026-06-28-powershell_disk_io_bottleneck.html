PowerShell ile disk I/O darboğazı tespiti

Sunucu "yavaş" diye şikayet geliyor, Task Manager'da CPU %12, RAM yarı boş. Sorun çoğu zaman ekranda görünmez — disk kuyruğunda birikir. Avg. Disk Queue Length 1'in üzerine çıktığı anda, her işlem disk için sırada bekler ve bu, kullanıcının hissettiği "yavaşlığın" gerçek kaynağıdır.

Windows performans sayaçları arasında en çok kafa karıştıran grup disk sayaçlarıdır, çünkü bazıları doğrudan ölçüm, bazıları türetilmiş (derived) değerdir. Sorun şu: CPU ve RAM grafikleri sakin görünürken, disk kuyruğu sessizce birikip uygulama yanıt sürelerini saniyelere taşıyabilir.

Disk I/O sayaçları nedir, ne anlatır?

Sayaç verisini Get-Counter '\PhysicalDisk(*)\Avg. Disk Queue Length' ile veya aşağıdaki teşhis scriptiyle toplayın. Eşikler genel kabul gören sysadmin pratiğine dayanır; ortamınıza göre ayarlayın.

Hızlı teşhis scripti

Aşağıdaki script, fiziksel diskler için temel sayaçları 5 saniyelik aralıklarla 12 örnek (1 dakika) toplar ve ortalamayı raporlar:

# diskio-diagnose.ps1 — temel disk darboğazı teşhisi
$counters = @(
    '\PhysicalDisk(*)\Avg. Disk Queue Length',
    '\PhysicalDisk(*)\Avg. Disk sec/Transfer',
    '\PhysicalDisk(*)\% Idle Time',
    '\PhysicalDisk(*)\Disk Transfers/sec'
)

$samples = Get-Counter -Counter $counters -SampleInterval 5 -MaxSamples 12

$results = foreach ($sample in $samples) {
    $sample.CounterSamples | Where-Object { $_.InstanceName -ne '_total' }
}

$results |
    Group-Object InstanceName |
    ForEach-Object {
        $name = $_.Name
        $queue = ($_.Group | Where-Object Path -like '*queue length*' |
            Measure-Object CookedValue -Average).Average
        $latencyMs = ($_.Group | Where-Object Path -like '*sec/transfer*' |
            Measure-Object CookedValue -Average).Average * 1000
        $idle = ($_.Group | Where-Object Path -like '*idle time*' |
            Measure-Object CookedValue -Average).Average

        [PSCustomObject]@{
            Disk             = $name
            AvgQueueLength   = [math]::Round($queue, 2)
            AvgLatencyMs     = [math]::Round($latencyMs, 2)
            IdleTimePercent  = [math]::Round($idle, 1)
            Durum            = if ($queue -gt 2 -and $idle -lt 20) { 'DARBOĞAZ ŞÜPHESİ' } else { 'Normal' }
        }
    } | Format-Table -AutoSize
# Örnek çıktı
Disk        AvgQueueLength AvgLatencyMs IdleTimePercent Durum
----        -------------- ------------ --------------- -----
0 C:        3.42           28.6         12.3            DARBOĞAZ ŞÜPHESİ
1 D:        0.08           1.1          97.8            Normal

Hangi process disk'i tıkıyor: process bazlı izleme

Diskin tıkandığını anladıktan sonraki adım, "kim yazıyor" sorusunun cevabı. Win32_PerfFormattedData_PerfProc_Process WMI sınıfı, process bazlı okuma/yazma byte oranını saniyelik olarak verir.

# top-disk-io-process.ps1 — en çok disk I/O üreten process'leri listele
function Get-TopDiskIOProcess {
    param([int]$Top = 10)

    Get-CimInstance -ClassName Win32_PerfFormattedData_PerfProc_Process |
        Where-Object { $_.Name -notin '_Total', 'Idle' -and $_.IODataBytesPersec -gt 0 } |
        Sort-Object IODataBytesPersec -Descending |
        Select-Object -First $Top -Property `
            Name,
            IDProcess,
            @{N = 'Read MB/s';  E = { [math]::Round($_.IOReadBytesPersec  / 1MB, 2) } },
            @{N = 'Write MB/s'; E = { [math]::Round($_.IOWriteBytesPersec / 1MB, 2) } },
            @{N = 'Total MB/s'; E = { [math]::Round($_.IODataBytesPersec  / 1MB, 2) } }
}

Get-TopDiskIOProcess -Top 10 | Format-Table -AutoSize

# Sürekli izleme: her 5 saniyede bir top 5 process
while ($true) {
    Clear-Host
    Get-Date | Write-Host -ForegroundColor Cyan
    Get-TopDiskIOProcess -Top 5 | Format-Table -AutoSize
    Start-Sleep -Seconds 5
}
Önemli not: Bu sayaçlar saniyelik anlık değerdir; tek bir ölçüm yanıltıcı olabilir. Gerçek darboğaz tespiti için aynı script'i bir döngüde 30-60 saniye çalıştırıp ortalama almak daha güvenilir sonuç verir.

Disk gecikmesi ile uygulama yanıt süresi ilişkisi

Avg. Disk sec/Transfer değeri, kullanıcıların hissettiği yavaşlamayla doğrudan ilişkilidir, ama yorumlama disk tipine göre değişir.

Disk tipiBeklenen sec/TransferÜzerinde olursa anlamı
HDD (7200rpm)5-15 ms> 25 ms ise ciddi darboğaz
SATA SSD0.1-1 ms> 5 ms ise anormal, controller/sürücü sorunu olabilir
NVMe0.02-0.2 ms> 1 ms sürekliyse darboğaz işareti
 
# Disk tipine göre eşik kontrolü ve uyarı
$threshold = 0.005  # 5ms — SSD için makul üst sınır (saniye cinsinden)

$latency = (Get-Counter '\PhysicalDisk(0 C:)\Avg. Disk sec/Transfer').CounterSamples.CookedValue

if ($latency -gt $threshold) {
    Write-Warning "C: sürücüsünde gecikme eşiği aşıldı: $([math]::Round($latency*1000,2)) ms"
} else {
    Write-Host "C: sürücüsü normal aralıkta: $([math]::Round($latency*1000,2)) ms" -ForegroundColor Green
}

Çözümler: tespitten sonra ne yapılır

Defender tarama zamanlaması

Zamanlanmış taramaları düşük yoğunluklu saatlere kaydır; MsMpEng sık sık en üst sırada çıkar.

I/O çakışmasını önler

Pagefile'ı ayrı diske taşı

Pagefile aktif darboğaz kaynağıysa, sistem disk yerine ayrı bir SSD'ye yönlendir.

Sistem disk yükünü azaltır

SQL Server checkpoint ayarı

Log büyüme ve checkpoint interval ayarlarını disk değişiminden önce gözden geçir.

Donanım değişmeden çözülebilir

Otomatik günlük rapor

Teşhis scriptini zamanlanmış görev olarak kaydet, CSV'ye logla.

Tekil teşhisten sürekli izlemeye geçiş 
# Defender zamanlanmış tarama saatini değiştir
Set-MpPreference -ScanScheduleDay Everyday
Set-MpPreference -ScanScheduleTime 03:00:00
Set-MpPreference -ScanScheduleQuickScanTime 01:00:00

# Pagefile durumunu kontrol et
Get-CimInstance -ClassName Win32_PageFileUsage | Select-Object Name, AllocatedBaseSize, CurrentUsage

# Görev zamanlayıcıya günlük rapor için kayıt
$action = New-ScheduledTaskAction -Execute 'powershell.exe' `
    -Argument '-File C:\Scripts\diskio-diagnose.ps1 -OutFile C:\Logs\diskio-daily.csv'
$trigger = New-ScheduledTaskTrigger -Daily -At 9am
Register-ScheduledTask -TaskName 'DiskIO-Daily-Report' -Action $action -Trigger $trigger

Genel disk I/O darboğazı kontrol listesi

  • Avg. Disk Queue Length değerini sürekli 2'nin üzerinde olan disk var mı kontrol et
  • % Idle Time düşükken (< %20) hangi process'lerin aktif olduğunu Win32_PerfFormattedData_PerfProc_Process ile listele
  • Antivirüs/EDR taramalarının zamanlamasını iş yükü saatlerine göre ayarla
  • SSD/NVMe sürücülerde sec/Transfer değerinin milisaniyenin altında kaldığını doğrula
  • Tek seferlik ölçüm yerine en az 30-60 saniyelik örnekleme ile sonuçları doğrula
  • SQL Server, Exchange gibi I/O-yoğun servislerin kendi log/checkpoint ayarlarını disk değişiminden önce incele
  • Sonuçları periyodik olarak CSV'ye loglayan bir zamanlanmış görev kur, tek seferlik teşhisle yetinme
  • Pagefile ve geçici dosya dizinlerinin (%TEMP%, IIS log'ları) ayrı bir diske taşınmasını değerlendir

Windows Update'in gizli ağ ve disk tüketimi: BITS ve Delivery Optimization

Bağlantınız aniden yavaşlar, disk ışığı sürekli yanar, ama Task Manager'da "Windows Update" diye bir şey görünmez — çünkü iş svchost.exe arkasında DoSvc ve BITS servisleri tarafından yürütülür. Üstelik komşu bilgisayarınız da sizin indirdiğiniz güncellemeyi internetten değil, sizin makinenizden çekebilir. Bunun farkına varmak için sayaç okumanız gerekir; arayüzde hiçbir uyarı yoktur.

Windows Update içeriği iki ayrı mekanizmayla dağıtılır: Delivery Optimization (DO) peer-to-peer model ile güncelleme parçalarını yerel ağdaki veya internetteki diğer Windows cihazlarından çeker; BITS (Background Intelligent Transfer Service) ise geleneksel arka plan indirme motorudur ve WSUS/SCCM ortamlarında halen aktif rol oynar. İkisi de varsayılan olarak "akıllı" bant genişliği ayarlamasına güvenir — yani siz video izlerken bile arka planda GB'lerce veri taşıyabilirler.

Ölçüm: Delivery Optimization performans anlık görüntüsü

Windows'un kendi Get-DeliveryOptimizationPerfSnap ve Get-DeliveryOptimizationStatus cmdlet'leri, dosyanın hangi kaynaktan (HTTP, peer, Microsoft Connected Cache) geldiğini ve ne kadar bant genişliği kullanıldığını doğrudan rapor eder. 

# do-network-snapshot.ps1 — Delivery Optimization genel görünüm
Get-DeliveryOptimizationPerfSnap | Format-List

# Aktif indirme/yükleme işlerinin detayı
Get-DeliveryOptimizationStatus | Format-Table FileId, Status, PercentPeerCaching, BytesTotal, BytesFromPeers, BytesFromHttp -AutoSize

# Bu ay toplam ne kadar veri taşındı (download + upload)
Get-DeliveryOptimizationPerfSnapThisMonth | Format-List
# Örnek çıktı
NumberOfFiles            : 14
TotalBytesDownloaded      : 3221225472
TotalBytesUploaded        : 891289600
DownloadHttpBytes         : 1073741824
DownloadPeerBytes         : 2147483648
PercentPeerCaching        : 66.6
Dikkat çeken nokta: Yukarıdaki örnekte indirilen verinin %66.6'sı peer'lerden gelmiş — yani bu makine internetten az veri çekmiş, ama karşılığında 891 MB veriyi başka cihazlara yüklemiş. Bu yükleme trafiği, özellikle sınırlı yukarı bant genişliğine sahip bağlantılarda fark edilmeyen bir tüketimdir.

# do-cache-size.ps1 — DO yerel cache disk kullanımı
$doCache = "$env:SystemRoot\SoftwareDistribution\DeliveryOptimization"
if (Test-Path $doCache) {
    $size = (Get-ChildItem $doCache -Recurse -ErrorAction SilentlyContinue |
        Measure-Object -Property Length -Sum).Sum / 1MB
    "{0:N1} MB — {1}" -f $size, $doCache
}

# Aktif BITS işlerini listele (varsa WSUS/SCCM indirmeleri)
Get-BitsTransfer -AllUsers | Select-Object DisplayName, JobState, BytesTotal, BytesTransferred

# Peer bağlantı detaylarını gör (kimlerle veri paylaşıyorsunuz)
Get-DeliveryOptimizationStatus -PeerInfo

Disk alanı şişmesini önler

1. Delivery Optimization bant genişliğini KB/s olarak sabitle

# Arka plan indirmeyi 1000 KB/s, ön planı 5000 KB/s ile sınırla
Set-DOMaxBackgroundBandwidth -MaxBackgroundBandwidth 1000
Set-DOMaxForegroundBandwidth -MaxForegroundBandwidth 5000

# Alternatif: yüzde tabanlı sınırlama (varsayılan: arka plan %45, ön plan %90)
Set-DOPercentageMaxBackgroundBandwidth -MaxBackgroundBandwidthPercentage 15
Set-DOPercentageMaxForegroundBandwidth -MaxForegroundBandwidthPercentage 50

# Varsayılana sıfırlamak için
Set-DOMaxBackgroundBandwidth -Reset
Set-DOPercentageMaxBackgroundBandwidth -Reset

# Aktif ayarları doğrula
Get-DOPercentageMaxBackgroundBandwidth
Get-DOPercentageMaxForegroundBandwidth
Get-DODownloadMode

2. Peer-to-peer yüklemesini sınırla veya kapat

# DODownloadMode değerleri: 0=HTTP only (peer kapalı), 1=LAN, 2=Group, 3=Internet
New-Item -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\DeliveryOptimization" -Force | Out-Null
Set-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\DeliveryOptimization" `
    -Name "DODownloadMode" -Value 0 -Type DWord

# Yalnızca yerel ağdaki cihazlarla paylaş (internet peering kapalı)
Set-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\DeliveryOptimization" `
    -Name "DODownloadMode" -Value 1 -Type DWord

# Değişikliği uygulamak için servisi yeniden başlat
Restart-Service -Name DoSvc -Force

3. BITS'i zaman aralığına göre sınırla

# Mesai saatlerinde (08-17) 20 Kbps, dışında 5000 Kbps ile sınırla
$bitsPath = "HKLM:\SOFTWARE\Policies\Microsoft\Windows\BITS"
New-Item -Path $bitsPath -Force | Out-Null

Set-ItemProperty -Path $bitsPath -Name "EnableBITSMaxBandwidth"     -Value 1     -Type DWord
Set-ItemProperty -Path $bitsPath -Name "MaxBandwidthValidFrom"      -Value 8     -Type DWord
Set-ItemProperty -Path $bitsPath -Name "MaxBandwidthValidTo"        -Value 17    -Type DWord
Set-ItemProperty -Path $bitsPath -Name "MaxTransferRateOnSchedule"  -Value 20    -Type DWord
Set-ItemProperty -Path $bitsPath -Name "MaxTransferRateOffSchedule" -Value 5000  -Type DWord
Set-ItemProperty -Path $bitsPath -Name "UseSystemMaximum"           -Value 1     -Type DWord

Restart-Service -Name BITS -Force

4. DO cache boyutunu disk kapasitesine göre sınırla

# Cache'i maksimum 5 GB ile sınırla (varsayılan davranış disk doluluğuna göre dinamiktir)
Set-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\DeliveryOptimization" `
    -Name "DOAbsoluteMaxCacheSize" -Value 5 -Type DWord

# Mevcut cache'i hemen temizle
Delete-DeliveryOptimizationCache -Force
Sıralama önerisi: Önce ölçüm scriptiyle hangi mekanizmanın (DO mu BITS mi) asıl tüketici olduğunu doğrulayın. Çoğu ev/küçük ofis ortamında asıl sorun DO peer yüklemesidir; BITS sınırlaması esas olarak WSUS/SCCM kullanan kurumsal ortamlarda anlamlıdır.

Genel Windows Update ağ/disk tüketimi kontrol listesi

  • Get-DeliveryOptimizationPerfSnap ile aylık toplam indirme/yükleme miktarını kontrol et
  • PercentPeerCaching yüksekse, yüklediğiniz veri miktarını BytesUploaded ile doğrula
  • Sınırlı yukarı bant genişliğinde DODownloadMode'u 0 (HTTP-only) veya 1 (LAN-only) yap
  • DO arka plan/ön plan bant genişliğini Set-DOPercentageMaxBackgroundBandwidth ile ortamına göre ayarla
  • WSUS/SCCM kullanılan ortamlarda BITS zaman aralığı sınırlamasını mesai saatlerine göre kur
  • DO yerel cache dizininin disk kullanımını periyodik olarak ölç, gerekirse DOAbsoluteMaxCacheSize ile sınırla
  • Port 7680 (TCP/UDP) üzerindeki peer trafiğini güvenlik duvarı loglarıyla çapraz kontrol et
  • Değişiklikleri GPO/registry ile kalıcı hale getir; tekil PowerShell komutları yeniden başlatmada sıfırlanabilir
